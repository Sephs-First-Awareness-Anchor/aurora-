# Aurora Perspective Before Resolution

**Date:** 2026-09-10  
**Authors:** Sunni (Sir) Morningstar & Ceph

## The correction

Build 714 already gives Aurora native adaptive representational resolution: she remains at the least-resolved representation sufficient to distinguish the consequences she is trying to distinguish, and only earns additional resolved fields when real consequence proves they are needed.

The missing precursor was cheaper than resolution.

A representation can fail to expose a distinction from one perspective even when the distinction is already latent in a real structurally-connected representation. In that case Aurora should first change the projection geometry rather than permanently add detail to the representation.

The canonical execution law is now:

```text
coarse representation
  -> real inadequacy pressure
  -> structurally connected representations
  -> lawful X/T/N/B/A perspective projection
  -> downstream consequence test
     -> projection distinguishes consequence: keep identity coarse
     -> projection does not distinguish consequence: try another lawful projection
     -> all lawful structural projections exhausted: Build 714 field inquiry
  -> only Build 714 evidence admission may retain a new field
```

## Projection is not resolution

A perspective projection is a transient view. It never changes `current_resolution()`, never writes `_active_resolutions`, never enters resolution genealogy, and never calls `resolve_field()`.

It may copy a field value only from a real structurally-connected `RepresentationalRef` already carrying that value independently. Bootstrap domain hypotheses are not mirrors and cannot be used as projection sources.

A projection is therefore analogous to an anamorphic image viewed through the right optical surface: the relation becomes legible because the coordinate transform changes, not because new information has been authored into the underlying object.

## Native projection geometry

Perspective uses the same 31 non-empty X/T/N/B/A pressure subsets already owned by `PredictiveStager`. No second perspective vocabulary is introduced.

The five Level-2 dimensions retain their established owners:

| Dimension | Native axis |
| --- | --- |
| MAGNITUDE | X |
| POLARITY | T |
| COST | N |
| DIFFERENCE | B |
| OPERATOR | A |

Axis-valued representational fields are owned by their own axis. A perspective exposes an unresolved field only when the field's already-existing source value belongs to an axis present in that lens.

This means one lens can expose several latent fields at once. For example, a T perspective may expose both an unresolved `sub_law_c=T` and `sub_law_d=POLARITY` from the same real source representation without resolving either field on the coarse representation.

## Causal sufficiency

Projection must participate in consequence to remain useful.

A consumer may read the projected view through the existing provisional-read seam. If the view produces a material downstream difference, the existing candidate-conditioned counterfactual record is sealed. When the real consequence arrives, Aurora compares baseline error with projection-conditioned error.

If the projection improves discrimination, no representational refinement is allowed for that event. The projection remains a transient optic only while inadequacy persists.

If a projection is read but produces no material downstream difference, or its conditioned consequence is no better than the coarse baseline, the lens is marked failed and Aurora may try another lawful projection. Only after available structural projections are exhausted does the original Build 714 field-inquiry path become reachable.

## Relationship to the live possibility frontier

PR #227 established:

```text
one frozen present
  -> multiple uncommitted continuations
  -> consequence/self comparison
  -> optional deeper self-simulation
  -> King identity arbitration
  -> one actualized continuation
```

Perspective-before-resolution provides the complementary representational law:

```text
one compact representation
  -> multiple lawful views
  -> enough distinction for the current continuation?
  -> use the cheapest sufficient view
  -> only grow representation if no view is sufficient
```

Both systems use the same native X/T/N/B/A perspective geometry. Possibility controls **which futures are allowed to remain live candidates**. Projection controls **how much of an existing representation must become legible to compare those futures or consequences**. Build 714 remains the authority for actual representational growth. Agency and the King remain the authority for actualizing a future.

## DCF interpretation

This is disciplined computational free will without a global thinking-depth governor.

Aurora does not ask for maximum detail. She pays for distinction only when distinction can change consequence or Agency. Perspective is the cheapest first move because it changes the view without changing identity. Resolution is the more expensive move because it permanently increases what the representation claims to know.

The resulting order is:

```text
Possibility -> Perspective -> Difference -> Resolution if necessary -> Simulation if necessary -> Agency -> Actuality
```

The stages are not a rigid global pipeline. They are causal permissions: expensive operations become lawful only when cheaper existing structure cannot settle the distinction required by the current situation.
