# Aurora Communication Trace Repair Directive

Date: 2026-09-11
Status: Investigation-active. This document accumulates confirmed defects while the end-to-end trace continues. Do not treat any single item as the root cause until the trace closes across multiple real failed turns.

## Governing repair law: representational conservation

Aurora may project a rich causal/relational representation into a smaller local view for a subsystem, but the projection must never replace the richer representation as the authoritative turn state. Causally relevant identity, participants, directed relations, Difference/contrast, provenance, developmental candidate identity, evidence identity, and perspective must remain recoverable and attributable through reasoning, expression, and delayed receiver consequence.

Do not repair this by making one giant PropositionFrame, adding intent classifiers, hardcoding English semantic templates, special-casing Sunni/Ceph, scripting abilities, or adding an external model. Preserve Aurora's constraint-native developmental architecture: unresolved pressure drives WARP/genealogy trials; successful distinctions earn standing through real consequence.

## Confirmed repair map

### 1. Live EmergenceMonitor disconnected
Live `boot_aurora` and batch `boot_stack` are not parity-equivalent for promoted-link capability surfacing. Mount one canonical EmergenceMonitor on the live genealogy/OETS instances, tick it at the intended lifecycle boundary, persist to the live state directory, and reconcile boot parity. Regression: a promoted Link on the live path becomes an emerged ability/OETS concept without a hardcoded ability name.

### 2. Representation resolver collapses identity/provenance to axis weights
`aurora_genealogy_representation_resolver.py` returns real genealogy `item_id` or temporary WARP `component_id` plus source/provenance, but working-memory consumption reduces the result to `constraint_basis`/axis weights. Preserve representation identity through live reasoning, understanding, expression, contributor capture, and trial consequence. Do not fabricate `genealogy.observe()` pressure. Regression: repeated novel distinction retains candidate identity, receives real consequence, and can earn promotion.

### 3. Referent grounding silently no-ops on nonexistent genealogy API
`aurora_referent_hypothesis.py::_sediment_validated_fact` gates the genealogy write on `hasattr(gen, "log_relief")`, but the live genealogy has no such API. Route validated referent correction through the actual canonical genealogy evidence/relief mechanism using real pressure/consequence. Regression: corrected referent becomes developmental evidence rather than only a transient clarification.

### 4. Internal failures become telemetry rather than experience
`aurora_internal/aurora_runtime_faults.py` intentionally records operational faults outside cognition. Preserve fail-soft recovery, but project internally consequential failures into the native developmental/consequence stream with stable failure signature and unique occurrence identity. Do not replay historical faults as present experience and guard against recursive fault projection. Regression: one controlled safe failure reaches both operational ledger and developmental path; later success can change the learned state.

### 5. Communication-emergence system is not production-mounted
`AuroraCommunicationEmergence` is designed to convert root-native communication deficits into WARP trials and receiver-validated promotion/dissolution, but production registration/boot mounting is absent while tests construct it manually. Instantiate one canonical live instance, attach canonical genealogy/SediMemory/WARP, register it, persist it in the live state directory, and expose it in systems.

### 6. Lexical-grounding system is not reliably production-installed
Install one canonical `AuroraLexicalGrounding`, attach live systems/genealogy, register it with WARP as required, call `install_lexical_grounding()` exactly once, and expose the same instance as `systems["lexical_grounding"]`. A lazy `persist=False` fallback must not masquerade as successful developmental observation.

### 7. Lexical consumption trace is never drained into live communication contributors
`drain_turn_consumption_trace()` exists specifically to attach exact `(candidate_id, evidence_id)` participation to an emitted response, but no live call was found. Drain the canonical instance once per emitted response into `contributors["lexical_grounding"]`; delayed receiver validation must call `record_evidence_outcome()` on those exact IDs. Historical replay must not enter the live trace.

### 8. Representation identity absent from live communication contributors
The finalizer understands representation contributors when tests manually provide them, but the live contributor builder has no demonstrated representation breadcrumb. Carry established genealogy `item_id` or temporary WARP `component_id` plus provenance into the live turn state and contributor trace, then route validated outcome through the existing representation communication-outcome mechanism.

### 9. Communication-emergence completed-turn handoff absent
Mounting the system is insufficient. After the real emitted response is finalized, call the canonical communication-emergence `observe_turn(...)` with the exact semantic state, response text/source/confidence and response ID. Preserve observation/trial ID in contributors; next-turn receiver evidence must close the same trial via `record_receiver_outcome()`.

### 10. Core relational identity loses relationship content in conversational activation
`CoreRelationalIdentity` contains rich entity records including relationship-to-Aurora, but spreading activation reduces an entity to name + role. Preserve stable entity identity/provenance and relational edges as first-class semantic material. Generalize to every entity. First-person identity claims must be able to become durable native relations when validated; do not create a special user-name slot.

### 11. PropositionFrame is too narrow for multi-participant/perspective relations
The current carrier centers on subject/relation/object/complement and cannot faithfully preserve arbitrary role-bearing participants such as perspective endpoint, recipient, source/destination, beneficiary, possessor, or comparison endpoint. Extend the semantic transport with role-bearing participants/edges or a graph-like relation payload while retaining the existing small slots as a local projection. Regression: `who is X?` and `who is X to you?` remain structurally distinct through reasoning and emission.

### 12. External evidence can outrank weakened internal relational evidence
The documented relational/self-question safeguard is not a reliable default live authority, while Scout evidence is live-wired. Do not repair with a phrase classifier. Evidence arbitration must use preserved relation fit, provenance, unresolved roles, perspective and confidence. A grounded internal relational configuration must not be overwritten merely because a participant token has a famous external homonym. Explicit external requests still admit Scout evidence.

### 13. Lexical developmental observation is relation-slot-bound
`extract_relational_form()` currently calls lexical grounding with `word=relation`. The grounding engine itself supports arbitrary subject/relation/object/complement geometry, but the integration observes only the parsed connective/relation. In a teaching turn such as `wanna is basically the same as want or to crave or desire`, the learner can therefore observe `is`/the scaffold rather than the lexical item being taught. Feed every materially participating developmentally uncertain lexical item to canonical lexical grounding according to its actual structural geometry and native gap/pressure. Do not hardcode `X means Y`, `same as`, or `wanna`.

### 14. Destructive projection across communication boundaries violates representational conservation
This is the cross-cutting defect exposed by both the relational-identity specimen and direct lexical-teaching specimen. Aurora already has rich inward relational/constraint structures and a `ProtoLanguage` explicitly intended as fully structured wordless comparison geometry before B-boundary expression. Yet intermediate communication structures repeatedly replace richer state with small projections. `SentenceComposer` receives PropositionFrame and directly binds its relation/object slots, so information discarded before the frame is not restored by expression.

Repair the architecture by making local frames/views projections with provenance, never authoritative replacements. Preserve a causal representation handle across: input relational extraction -> proposition/reasoning -> representation/genealogy/WARP -> ProtoLanguage/LanguageField -> expression -> emitted-response contributors -> delayed receiver consequence. Every transformation must either preserve causally relevant distinctions or explicitly mark an unresolved/lossy projection that creates developmental pressure rather than silently erasing information.

Acceptance must cover at least two structurally different real failures: relational identity (`who is X to you?`) and lexical contrast teaching (`novel word is near Y but differs by Z`). The repair passes only if the relevant relation/Difference can be followed end-to-end by stable identity/provenance and the exact contributing representation can receive later positive/negative receiver consequence.

## Global prohibitions

No external LLM/model as Aurora's intelligence. No hardcoded user/entity names. No hardcoded relationship-context intent detector. No canned synonym/definition parser as the developmental solution. No fabricated genealogy pressure or fake relief. No fallback that turns a developmental failure into apparent success. No duplicate Surface/Subsurface developmental instances. No immediate success credit where receiver validation is required.

## Investigation remains open

Continue tracing real failed conversation turns. At every meaningful boundary compare the incoming relational/semantic configuration to the outgoing representation. The first boundary that destroys a distinction required to uniquely answer the turn is a defect. Document the exact failure, location, causal consequence, native repair, prohibitions, and live-path regression test. Continue beyond each defect until the entire failed turn is causally closed.
